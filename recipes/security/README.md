# Security

Firewalls, identity and policy: FTD and FMC, ISE (802.1X, MAB, TrustSec), VPNs, and labs that integrate with external security appliances.

See [conventions](../../docs/conventions.md#categories) for which category a recipe belongs in.

<!-- catalog:start -->

| Recipe | What it builds | Nodes | Tier | Status | Version |
|---|---|---|---|---|---|
| [FTD internet edge with FMC](ftd-internet-edge/) | An FTDv internet edge managed by an FMCv in the same lab: the FTD registers itself at day 0, then FMC gives it zones, an access policy that blocks one site, a default route and PAT, so an inside host reaches a simulated internet that has no route back to it. | 4 | free | draft | 0.1.0 |
| [FTD SD-WAN with a backup hub](ftd-sdwan-dual-hub/) | Secure Firewall SD-WAN with a primary and a backup hub sharing a data center LAN, and two spokes, on FTDv managed by an FMC you already have: every spoke keeps an IPsec tunnel and an iBGP session to both hubs, prefers the primary, and moves to the backup when the primary fails. | 10 | personal | stable | 1.0.0 |
| [FTD SD-WAN with one hub](ftd-sdwan-single-hub/) | Secure Firewall SD-WAN with one hub and three spokes on FTDv, managed by an FMC you already have: three simulated carriers, a hub-and-spoke IPsec overlay over virtual tunnel interfaces with iBGP generated by FMC's SD-WAN wizard, and a backup tunnel over a second carrier for two spokes. | 11 | personal | stable | 1.0.1 |
| [FTD TLS cipher policy](ftd-tls-cipher-policy/) | An FTDv between a TLS client and a TLS server whose ports each pin a protocol version or cipher suite, managed by an FMC you already have: FTD logs the version and cipher of every TLS session to an in-lab syslog collector without decrypting it, then blocks old versions and weak ciphers, and a Decrypt - Resign rule shows what a terminating firewall does to the cipher on each side. | 3 | free | stable | 1.0.1 |
